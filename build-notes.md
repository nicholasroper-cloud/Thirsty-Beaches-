This repo is the live source the kiosks auto-pull.
- drink-kiosk.html / drink-kiosk-light.html = the kiosk screen
- update-manifest.json = version pointer (bump "version" to push a change)

## Release v39 notes (2026-11-19)

### The arcade (`/arcade`): on the kiosk's own screen since v40 (see the v40 section below); it is still its own URL
- Where it is: `http://localhost:8137/arcade` on the kiosk PC (the server listens on 127.0.0.1 only, so it can be opened by a browser on that PC, for example on a second screen). Nothing on the ordering screen links to it and none is added in this release. The arcade page has an "Order Drinks" link back to `/`.
- Files: `kiosk/*` (page, css, js, audio bank, menu) arrive through the manifest and are swapped in place; `arcade-routes.js` is server code (staged, idle restart, 60 s trial, automatic rollback like the other engine files).
- No camera, no microphone, no AI scan: the page never calls `getUserMedia` and is served with `Permissions-Policy: camera=(), microphone=()`. Scan My Vibe and the Presence Cam were removed.
- Prizes are real or absent. The kiosk server rolls the prize and asks the tb-where Worker for a claim code (play token + `/kitchen/claim` with `X-Kiosk-Key`). The page shows the Worker's code and nothing else; if the Worker is unreachable, `KIOSK_KEY` is unset, the daily cap (`PRIZE_DAILY_CAP`, shared with the website) is hit, or no play token is 45 s old yet, the result is "thanks for playing". The Worker needs its `PLAY_SECRET` and `KIOSK_KEY` secrets set. The code is a 4-character Kitchen Board claim: the make station's Claims drawer lists and redeems it. The page shows the prize itself ("Free Size Upgrade" ...) and, with the updated Worker, the staff Claims tab shows the same prize label; against an older Worker the Claims tab keeps the Worker's reward text ("Secret Menu Unlock").
- Staff drawer (tap the top-right corner three times): locked until the staff key is typed. The staff key is `STATION_KEY` from `kiosk-config.env`, the same key the make station uses; with it blank nobody can change anything (fails closed). Odds must list every prize once, be numbers 0 to 100, sum to 100, and free drink odds are capped at 2%. Persona, volume and mute are per screen and never touch the server.

### Make Station server: how it reaches the PC (it is NOT in the manifest)
`make-station-server.js` is a separate process (`Run-MakeStation.bat`, port 8140). The supervisor only manages `kiosk-server.js`, it cannot restart or roll back the station server, and the manifest has never carried it (`kiosk-lib.js` lists it as content, not engine). `make-station.html` IS in the manifest, so the page can arrive before the server. Decision: the new page degrades instead. Against a server without `/api/kitchen/extras` (404) the Claims and 86 Stock buttons are hidden and the ticket screen works as before.
Manual step to get the new station features on a PC that runs the local station (the cloud station at station.thirstybeaches.com is deployed separately):
1. Copy the new `make-station-server.js` from the repo (or the USB package) over the one in the Drive folder.
2. Stop the station (Stop-Kiosk.bat closes every node.exe, so do this at the end of the day, or close only the "Thirsty Beaches Make Station" window), then double-click `Run-MakeStation.bat`.
3. Open the station: Claims and 86 Stock appear within 20 seconds. For VIP passes the PC also needs `CROSS_BRAND_SECRET` in `kiosk-config.env`; without it a VIP pass answers "verify at the Salty Dog Tags order".

### Catalog map (`catalog-map.json`)
113 of 118 items and 237 of 304 modifier choices now carry their Clover id (each verified live, price equal). It is only read when `KIOSK_ORDER_TYPE_ID` is set, so with the kiosk's current config (blank order type, blank `CATALOG_TAX_RATES`, `PAY_ENABLED=false`) nothing changes: legacy window-pay orders. `tests/kiosk/map-inert.js` proves it. Turning on server-side pricing later needs the Clover "Kiosk" order type, a tax decision and `CATALOG_TAX_RATES` (see `catalog-gap-report.md`).

### An arcade win rides the order (added to v39, 2026-11-19)
Flow in five lines:
1. A spin that wins gets a real 4-character claim from the Worker (`POST /kitchen/claim` with `X-Kiosk-Key`; the kiosk now also names the prize id, and the Worker stores it on the claim).
2. The kiosk server keeps that win as the ONE pending prize (code, prize id, label, issuedAt) for 15 minutes, in memory and in `.tb/arcade-pending.json`. A newer win replaces it. `GET /api/arcade/pending` reads it, `POST /api/arcade/pending/dismiss` declines it. Nothing in the browser can create one.
3. The arcade page shows the prize, the code and a big "Order now and use it" button (to `/#menu`, same display) plus the two-screen line. The order screen polls the pending prize and shows "Arcade win: <prize>. It's attached to this order, show nothing, we've got it." with a "No thanks" button.
4. After the order is placed the page sends ONLY the new order id to `POST /api/arcade/pending/attach`. The server checks that Clover says it is a fresh kiosk order, then appends ` · ARCADE <prizeId> <CODE>` to that order's note (the same carrier as ` · MAZE UPSIZE`) and clears the pending prize. If the write fails the page retries, then tells the customer to mention the code at the window.
5. The Make Station reads the tag from the ticket's order note and shows a cyan "ARCADE WIN: <prize> · CODE" badge on the ticket tile, the NOW header and the NEXT pane. Bumping the ticket (or tapping the badge) redeems the claim through the existing `/api/kitchen/redeem` relay with the ticket number; the redeem is queued in the browser and retried while the relay is offline. The pickup board never reads the note, so it is unchanged.

What it does NOT touch: no price, total, discount, tax or Clover line item, no change to `/quote`, `/order`, `/pay`, `flex-pay.js`, `pay-routes.js`, `quote.js`, `pay-journal.js` or `kiosk-lib.js` (all byte-identical to the reviewed pay path). The only Clover write the prize makes is one extra `POST /orders/<id>` whose body is `{note}`, sent after the order exists. The prize is honoured by crew at the window; with `PAY_ENABLED=true` the charged amount is still whatever the quote says. The page sends no prize id, label or code, and the Worker only stores a prize when the request passes its kiosk-key check and the id is on its fixed allow-list. A badge typed by hand into a note is harmless: the redeem relay only marks a real, unredeemed Worker claim.
Left to decide: the pending prize belongs to the kiosk, not a person. If the winner walks away, the next customer to open the order screen within 15 minutes sees the banner and can tap "No thanks" (their win stays a code on the arcade page).

Old station server (`make-station-server.js` not yet copied to the PC): the badge still shows, because the page reads the ticket note that every server already passes through (`orderNote`). What it cannot do is redeem: the old relay has no `order` field and, on a server from before the Kitchen Board update, no `/api/kitchen/redeem` at all, so the badge says "this station cannot redeem yet" and the crew redeem the code in the Claims tab or at the Worker. Orders print and show exactly as before. To get bump-to-redeem with the ticket number, copy the new `make-station-server.js` (same steps as above). The cloud station gets the same page; its relay needs a Worker deploy of `cloud/src/kitchen-sync.js`.

Release order: (1) Worker `worker-tb-where` (accepts `prize` on `/kitchen/claim` and `order` on redeem; harmless to an older kiosk, which sends neither), through dev first; (2) the cloud station (`cd cloud && node build.js && npx wrangler@4 deploy`: new relay field, phone menu with the new soft-serve names); (3) the kiosk push (manifest v39). The kiosk works against an old Worker too: the claim is minted the same, only the Claims tab text stays "Secret Menu Unlock".

### The arcade on the kiosk's own screen (manifest v40, 2026-11-19)
- Entry: a "Play & win / Boardwalk Arcade" button on the ordering screen, in the strip just above the category tabs (low on the screen, a child can reach it), and a smaller secondary button under "Tap to begin" on the attract screen. `drink-kiosk.html` and `drink-kiosk-light.html` stay byte-identical. The only way in is `goArcade()` in the page.
- Cart guard: the entry is HIDDEN while the cart has anything in it (and `goArcade` refuses while an order or payment is in flight), so a cart can never be lost by a tap. With an empty cart there is nothing to preserve. A win comes back as the order-screen banner (the kiosk server holds the pending prize for 15 minutes).
- The way back: a permanent full-width "ORDER DRINKS" button at the bottom of the arcade (to `/#menu`), "Order now and use it" after a win, and a hands-off return to `/` (the attract screen) after `idleSeconds`, with a "Still playing?" warning `idleWarnSeconds` before.
- One visit is limited (anti line-holding): `kiosk/arcade-session.json`, defaults 3 spins or 90 seconds, whichever first (a spin in progress always finishes), then "Thanks for playing" and the reels stop; the thanks screen returns to `/` after `endedReturnSeconds` (30). A missing or invalid file falls back to the defaults, never to "no limit"; `"enabled": false` switches the limit and the idle return off (second-screen use). Prize odds, the daily cap and the 2% free-drink ceiling are NOT here; the Worker and `arcade-routes.js` enforce those.
- Idle restart: an open arcade page counts as customer activity (`/arcade` and a 20 s `GET /api/arcade/ping` are in `ACTIVITY_PATHS`), so the engine never restarts mid-game; the order screen's own 4 s prize poll deliberately is not. An abandoned arcade page can hold a restart or the new-version reload back for at most the idle time, because leaving it is a full page navigation to `/`, which loads the newest build.
- Audio: the kiosk ships no sound files. A missing clip is requested once, then the Web Speech / synthesized fallback is used with no further 404s; the audio bank is optional (if it fails to load the arcade plays silently). `stopAll()` runs when the visit ends and on page hide: music, voice and the AudioContext stop and nothing can start again.
- Test: `node tests/kiosk/arcade-prize.js` (section D, headless Chrome; `TB_SHOTS=<dir>` writes the screenshots) and `tests/boardwalk-arcade.test.mjs`.


## Release v44 notes (2026-11-20): five touch games on the kiosk, prizes that follow the customer to a later order

THIS RELEASE CHANGES ENGINE FILES (`kiosk-server.js`, `arcade-routes.js`): it goes through the supervisor like v39-v43 (sha256, self-test, 60 s trial, automatic rollback). Push it outside service hours.

### The games
- Picker `http://localhost:8137/arcade/games`; games `/arcade/games/<id>` for `thirsty-blaster`, `thirsty-tower`, `cup-catch`, `boardwalk-dash`, `soft-serve-stacker`. Files live in `kiosk/games/` (shared shell `kiosk/games/shared/`, local fonts `kiosk/games/fonts/`); the manifest tool ships the whole folder. The slot machine stays at `/arcade`; it links to the picker ("More games") and the picker links back.
- Offline: the game pages are served under a CSP of `default-src 'none'; script-src 'self'; ... connect-src 'self'` (no external host can be loaded or contacted; no inline script), fonts are shipped (OFL), nothing links to the website.
- Layout is portrait first (47-inch panel, 1080x1920): title/score/time bar at the top (display only), the board as large as the height allows, controls in the lower part, a permanent bottom bar with ALL GAMES and ORDER DRINKS. Landscape stacks the same way and does not overlap the bar.
- One visit = the picker plus all five games: `gameMaxSeconds` (default 150) counts from the first game page of the visit (kept in sessionStorage, no personal data). At the cap: "Time's up", audio stopped, ORDER DRINKS, return to `/` after `endedReturnSeconds`. Same "Still playing?" warning, hands-off return and 20 s ping as the slots page (`/arcade/games*` and the ping count as customer activity, so the engine never restarts mid-game). On a hands-off or ended return the page first clears the kiosk's pending prize (walk-away rule); ORDER DRINKS does not.
- Static serving: `/kiosk/*` is root-contained (no `..`, no NUL, no backslash) and now also an extension allowlist (html css js json woff2 svg png webp mp3 wav txt); game pages are served only for the five ids above.

### Prizes from the games, and using a prize on a later order
Everything uses the SAME pipeline as a slot spin (arcade-routes.js): staff odds table, tb-where Worker code (play token, global daily cap, 2% free-drink ceiling), ONE pending prize for 15 minutes, order-screen banner, ` · ARCADE <prizeId> <CODE>` appended to the Clover order note after the order exists, ARCADE WIN badge on the make-station ticket, redeem on bump. No price, total, discount or line item changes anywhere.
New endpoints (all on the kiosk server, loopback, same-origin, JSON):
| Endpoint | The page may send | What the server trusts |
|---|---|---|
| `POST /api/arcade/game/start` | `{game}` from the five ids | only the id; opens a session on the server clock |
| `POST /api/arcade/game/finish` | `{sid}` | only a session this server opened, not finished, older than `gameMinSeconds`; one roll per session; shared per-visit cap `maxPrizeRolls` (slots + games); a per-minute limiter. Score, prize, label, code in the body are never read. Result is a chance roll at the staff odds, never a reward for a score |
| `POST /api/arcade/wallet/save` | `{phone, code}` | the code only as a SELECTOR: it must be a win this server issued in the last 6 h; the number is passed to the station Worker and never logged or stored here |
| `POST /api/arcade/wallet/lookup` | `{phone}` | prize id and expiry from the station Worker's answer; the label always from this server's own table; rate limited (8 per 10 min, 60 per day per kiosk) |
| `POST /api/arcade/code` | `{code}` | the tb-where Worker's check-only answer (prize must be an arcade prize, not expired, not already redeemed); a code already attached to an order here is refused until it is bumped |
| `GET /api/arcade/status` | nothing | says whether prizes can be issued and whether the Worker's daily cap is known to be used up (the pages say "Prizes are done for today" BEFORE play) |
| `GET /api/arcade/rules` | nothing | facts for the Prize Game Rules panel (from `kiosk/arcade-rules.json` + the live odds table) |
- Settings in `kiosk/arcade-session.json` (a missing or bad value falls back to the default, never to "no limit"): `maxPrizeRolls` 4, `useOnSameVisit` true (false = the win is NOT made the pending prize and no banner shows; the customer only gets the code / phone link), `gameMinSeconds` 20, `visitGapSeconds` 120, `gameMaxSeconds` 150.
- Staff config (`arcade-config.json`, drawer or `POST /api/arcade-config`) now also carries `period` (a short label for the promotion period) and a `version` counter bumped on every real odds/period change; every win logs `arcade: win <prizeId> via game|slot period=<p> odds-v=<n>` (never the code).
- The daily cap, once the Worker says it is used up, is remembered until local midnight (restart the kiosk to re-probe sooner).
- Game results are plain: the free-drink prize is called "Free Drink" on a game result and in the rules panel, there is no mega flag or sound trigger. The slot machine is unchanged.

### Phone number lookup (prize only, not marketing)
- Home: the STATION Worker (`cloud/src/prize-link.js`, KV `STATE`). A kiosk PC file would not survive a PC change and could not serve the phone-order page or the window; tb-where is not in this repo. The kiosk calls it with `X-Key: STATION_KEY`; the Worker re-verifies every claim with tb-where (check only) so the kiosk is not trusted for prize, label or expiry.
- Stored: only `HMAC-SHA256(PRIZE_PHONE_KEY, "tb-prize-phone|+1" + 10 digits)` as the KV key, with the claim code, prize id and expiry; TTL = the claim's own expiry; deleted when the prize is attached on the kiosk and when the make station redeems. One unredeemed prize per number; a new win never replaces it. Nothing in this store is shared with the tide-list / SMS consent records (those live in tb-where) or the punch card (a stateless token); no message of any kind is sent to a prize number.
- DEPLOY (not done): `openssl rand -hex 32`, `cd cloud && npx wrangler secret put PRIZE_PHONE_KEY`, then build + deploy the station Worker (CI deploys on push to main: service-day freeze applies). Until then "Save to phone" answers "off" and the code stays the only way.
- Claim lifetime: tb-where mints a claim with a 24 hour expiry (KV 30 hours). The screens say "24 hours" from `kiosk/arcade-rules.json` `prizeLifeText` and from each win's own `expiresAt`. To make it 30 days change `expiresAt: now + 24 * 3600e3` and `expirationTtl: 60 * 60 * 30` in `worker-tb-where/src/routes/kitchen.js` `mintKitchenCode` (and then `prizeLifeText`).

### Make station on the PC
`make-station-server.js` is a separate node process (`Run-MakeStation.bat`), not the supervised kiosk server, so the supervisor cannot restart or roll it back; the manifest deliberately has never carried it (`kiosk-lib.js` CONTENT_JS). Shipping it as a plain file would put unreviewed code where the next manual start loads it with no trial and no rollback, and the running process would ignore it anyway. It is unchanged in v44. Until the hand step (copy the file from the repo/USB package, close the "Thirsty Beaches Make Station" window, run `Run-MakeStation.bat`) a game win renders on the ticket exactly like a slot win (the page reads the order note), but bump-to-redeem is unavailable on that station and crew redeem in the Claims drawer or at the cloud station, whose relay already redeems after a Worker deploy of `cloud/src/kitchen-sync.js`.

- Age check before any phone field (win screen and order screen, phone path only): neutral birth month + year, no defaults, under 13 (<= 156 months) goes to the code, stores nothing, and the phone path is not offered again until the visit/order screen resets (`sessionStorage.tbPhonePathOff = "1"`, a bare flag, shared by the arcade pages and the order page). The code path never asks age. No "ask a grown-up" wording anywhere.

- Game results are plain (no reels/wheel/scratch, no coin sounds, none of "jackpot", "spin to win", "bet"); the free-drink prize reads "Free Drink" on games. The slot machine is unchanged.
